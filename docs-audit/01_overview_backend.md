## Executive Summary

PulseMeet is a browser-native, peer-to-peer (P2P) real-time video conferencing application built with the MERN stack (MongoDB, Express, React, Node.js), native browser WebRTC, and Socket.io. The project is organized as two independent packages (`backend` and `frontend`) within a single repository root rather than a formal workspace monorepo.

The backend is lightweight (approx. 390 lines of JavaScript source code) handling stateless JWT user registration, authentication, meeting activity history, and Socket.io signaling. The frontend is a single-page React 18 application (approx. 4,500 lines of JSX and CSS Modules) incorporating WebRTC mesh peer connection negotiation, Web Audio API active speaker detection, client-side MediaRecorder recording, and instant chat.

### 2. Monorepo vs Separate Packages, Node & Tooling

- **Repository Structure:** Two distinct directories (`/backend` and `/frontend`). Not a managed monorepo (no Lerna, Turborepo, Nx, npm workspaces, or pnpm workspaces). Root contains only `.git`, `.gitignore`, and `README.md`.
- **Package Manager:** `npm` (npm lockfile v3 in both backend and frontend).
- **Node Version Compatibility:** Tested and verified on Node `v24.13.1` (npm `11.10.0`). Neither `package.json` specifies an `engines` block.
- **Frontend Build Tool:** Create React App (`react-scripts` 5.0.1, Webpack 5, Babel).
- **Backend Execution:** Plain Node.js with native ES Modules (`"type": "module"` in `backend/package.json`).
- **NPM Scripts:**
  - Backend:
    - `"dev": "nodemon src/app.js"`
    - `"start": "node src/app.js"`
    - `"prod": "pm2 src/app.js"`
  - Frontend:
    - `"start": "react-scripts start"`
    - `"build": "react-scripts build"`
    - `"test": "react-scripts test"`
    - `"eject": "react-scripts eject"`

### 3. Outdated, Deprecated & Vulnerability Observations

1. **Create React App (`react-scripts` 5.0.1):** CRA has been officially deprecated by the React team. It depends on `@babel/plugin-proposal-private-property-in-object` (unmaintained) and triggers Node 24 runtime warnings (`fs.F_OK is deprecated`).
2. **`crypto` package in backend (`package.json#L17`):** Npm `crypto` v1.0.1 is an obsolete dummy package published 10+ years ago. Should be purged (`npm rm crypto`).
3. **`http-status` Version Discrepancy:** Backend uses `http-status` `^2.1.0` while frontend uses `^1.7.3`. While functional, aligning versions reduces cognitive overhead.

### 2. Middleware Execution Pipeline

In [`backend/src/app.js`](file:///d:/Desktop/ZOOM/backend/src/app.js):
1. `cors()`: Permissive CORS configuration (`origin: "*"`).
2. `express.json({ limit: "40kb" })`: Parses JSON request payloads up to 40KB.
3. `express.urlencoded({ limit: "40kb", extended: true })`: Parses URL-encoded data.
4. Route-level middleware `authenticateToken` ([`backend/src/middlewares/auth.middleware.js`](file:///d:/Desktop/ZOOM/backend/src/middlewares/auth.middleware.js)):
   - Checks `Authorization: Bearer <token>`, with fallback to `req.query.token` or `req.body.token`.
   - Executes `jwt.verify(token, JWT_SECRET)`.
   - Attaches `req.user = decoded;` and invokes `next()`.
   - Returns `401 Unauthorized` on missing token or expired token (`TokenExpiredError`).
   - Returns `403 Forbidden` on malformed/invalid signature.
5. **Missing Global Error Handler:** The app lacks an Express error handling middleware `(err, req, res, next) => {}`. Unhandled promise rejections in routes crash the request without a structured error envelope.

### 3. Mongoose Schemas & Database Models

#### User Model ([`backend/src/models/user.model.js`](file:///d:/Desktop/ZOOM/backend/src/models/user.model.js))
```javascript
const userSchema = new Schema({
    name: { type: String, required: true },
    username: { type: String, required: true, unique: true },
    password: { type: String, required: true },
    token: { type: String }
});
```
- **Indexes:** `username` (unique index created by MongoDB).
- **Security Vulnerability:** `user.token` is written to MongoDB upon login, but never verified during subsequent requests (the app relies purely on stateless JWT signature verification). Furthermore, if `User.find()` is queried without projection, the hashed `password` and `token` are returned.

#### Meeting Model ([`backend/src/models/meeting.model.js`](file:///d:/Desktop/ZOOM/backend/src/models/meeting.model.js))
```javascript
const meetingSchema = new Schema({
    user_id: { type: String }, // Stores username string, not ObjectId reference
    meetingCode: { type: String, required: true },
    date: { type: Date, default: Date.now, required: true }
});
```
- **Indexes:** None explicitly configured. `Meeting.find({ user_id: username }).sort({ date: -1 })` executes a full collection scan without a compound index on `{ user_id: 1, date: -1 }`.
- **Relations:** No Mongoose `ref` to `User` model; stores `user_id` as a loose string (`user.username`).

#### Socket Events Specification Table

| Event Name | Direction | Payload Shape | Handler Logic / Behavior |
| :--- | :--- | :--- | :--- |

| `signal` | Client -> Server | `toId: String, message: String` | Relays WebRTC SDP Offer/Answer or ICE Candidate directly to target peer (`io.to(toId).emit('signal', socket.id, message)`). |
| `signal` | Server -> Client | `fromId: String, message: String` | Target peer receives the relay signal. |
| `chat-message` | Client -> Server | `data: String, sender: String` | In-call chat broadcast: `io.to(socket.roomCode).emit('chat-message', data, sender, socket.id)`. |

| `user-raised-hand`| Server -> Client | `{ socketId: String, username: String, isHandRaised: Boolean }` | Displays hand raise banner across room peers. |
| `disconnect` | Client -> Server | N/A | Triggered when WebSocket drops. Broadcasts `socket.to(roomCode).emit('user-left', socket.id)`. |
| `user-left` | Server -> Client | `socket.id: String` | Peers close and delete the `RTCPeerConnection` for that socket ID. |

#### Room Lifecycle & Memory vs Database Storage
- **Room Creation:** Rooms are dynamically created on-the-fly when the first socket calls `socket.join(roomCode)`.
- **Room Cleanup:** When all sockets leave, Socket.io's in-memory adapter automatically garbage-collects the room.
- **Persistence:** **ZERO** socket data is saved to MongoDB. Rooms, peer lists, and messages exist solely in Node.js process memory.
- **Server Restart Impact:** If the backend restarts, all active WebSocket connections sever instantly. WebRTC peer connections will momentarily remain open until renegotiation or ICE failure, but signaling is destroyed.
- **Authentication & Access Control:** Sockets are completely unauthenticated (`io.use()` middleware is missing). Any client can join any room code with an arbitrary name.
